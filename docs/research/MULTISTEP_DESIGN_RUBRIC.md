# Multi-step design comparison

Compare the two completed candidates before choosing a production design. Do not
cross-judge while either candidate is still writing. Score each criterion 0–5 and
explain specific evidence. Correctness failures block selection regardless of total.

1. One effect authority and atomic predecessor/claim invariants. No duplicate after
   crash, false success from opening an app, continuation after uncertainty, or stale
   downstream binding after edits. Include full cancellation/restart/receipt failures.
2. Typed bounded proposals, dependencies and results that honor user intent. Actual
   Meta System1 decisions remain visible; deterministic gates and cloud planning have
   truthful separate provenance. Untrusted external text cannot introduce an action.
3. A usable native flow from voice/text through clarification, review, progress and
   recovery. Preserve incomplete intent and explain missing permissions/capabilities.
   Show partial completion without implying delivery or third-party UI control.
4. A small coherent implementation that reuses the catalog/journal/admission design.
   Judge interface depth, ownership, migration, bounded retention and what can be
   verified before submission. Reject a speculative general workflow platform.
5. Reproducible verification on real boundaries. Meaningful concurrency/storage tests,
   local-model routing tests and Xcode/iPhone checks must be distinguished. Identify
   the first implementation unit and the evidence required before any readiness claim.

The parent also reads both designs end to end and records base selection, grafts,
rejections and remaining platform limitations. No candidate is promoted by confidence
of prose or agreement alone. New independent review uses a fresh delegated task.
